# People-Analytics Warehouse

> **All data in this project is synthetic.** It is generated by a script for a fictional company
> ("Nodewell Labs") as a personal portfolio project. No real people, employers or HR records are involved.

A Visier-style people-analytics layer rebuilt on an open stack: a fake HRIS/ATS in Postgres,
synced by Fivetran and batch-loaded into BigQuery, modelled with dbt, exposed through LookML and
Data Studio dashboards, and benchmarked with a text-to-SQL AI-agent evaluation. It runs entirely
on free tiers with no payment card (BigQuery sandbox, Fivetran Free, Neon Free);
see [docs/decisions.md](docs/decisions.md).

## Quick start

```bash
make setup             # Python 3.12 venv + pinned requirements
cp .env.example .env   # then fill in your own values (never commit .env)
make setup-gcp         # one-time: BigQuery sandbox project (no billing), service account, datasets
make check             # GCP key guard, dbt debug, Postgres insert

make generate          # synthetic HRIS + ATS history -> generator/output/*.csv
make load              # first load into the source Postgres (schema hris)
make check-data        # row counts, FTE headcount, planted data-quality issues
make simulate-day      # one more business day of hires, moves and exits

make ingest SOURCE=direct   # load BigQuery raw_hris (SOURCE=direct until Fivetran is live)
make dbt-build              # dbt seeds, models and tests (TARGET=prod for the analytics dataset)
make storage-report         # bytes written so far vs the sandbox's 10 GiB lifetime allowance
```

Run `make help` for all targets.

## Nightly run (GitHub Actions)

[.github/workflows/dbt.yml](.github/workflows/dbt.yml) loads BigQuery, rebuilds the warehouse, reports
source freshness and storage, then simulates the next HR business day. It needs, under
Settings > Secrets and variables > Actions:

- secrets `BQ_SA_KEY_JSON` (the service-account key, whole JSON), `GCP_PROJECT_ID`, `POSTGRES_URL`,
  `LANDING_POSTGRES_URL`;
- variable `INGEST_SOURCE`: `direct` until the Fivetran connection is live, then `fivetran`;
- optional variable `PAUSE_SIMULATION` = `true` to stop the source moving (for example before a demo).

When something breaks, see the [schema drift](docs/runbook-schema-drift.md) and
[sync failure](docs/runbook-sync-failure.md) runbooks.
